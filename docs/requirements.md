# 要件定義 (Requirements)

## 1. 概要 (Overview)
* **タイトル案**: （未定）
* **ジャンル**: 全身アクションゲーム（もじもじくん風）
* **プラットフォーム**: PC (画面はプロジェクターに出力)

## 2. プレイヤー環境・トラッキング仕様
* **VRゴーグル**: **不使用**。プロジェクターの映像を見ながらプレイする。
* **トラッキング機器**: SmolSlime (SlimeVR互換)
* **トラッキング箇所**: 計11点（両腕4点、両足4点、胴体2点、頭1点）
* **連携方法**: OSC通信（SlimeVRから直接Unityへデータを送信する）
* **キャラクターへの反映 (IKアプローチ)**:
  * **第1候補**: SlimeVR側の計算結果（関節の回転データ）をOSCで受け取り、キャラクターの骨格に直接コピーする（無料・高精度）。
  * **第2候補**: Unity標準の「Animation Rigging」を使用し、トラッカー座標に合わせて手足を動かす（無料・要調整）。

## 3. ゲームの目的・コア体験 (Core Experience)
* 迫りくる壁（障害物）の穴の形に合わせて、全身でポーズをとって通り抜ける。
* リズムやタイミングに合わせてポーズを切り替える体験。
* 最後に「成功回数」を表示してスコアとする。

## 4. 画面・カメラ設定
* **視点**: 三人称視点（キャラクターの背中を後ろから見る形）
* **キャラクター**: シンプルなもの（棒人間など、全身のポーズが分かりやすいもの）

## 5. 主要なシステム・機能 (Main Features)
* **プレイヤーの移動制限**: 立ち位置は固定（横移動なし）。ポーズ（姿勢）のみで壁を避ける。
* **ステージ構成**: 1ステージあたりの壁の枚数は固定。事前に用意した複数の壁の穴パターンからランダムに出現。
* **難易度設定機能**: タイトル/設定画面から、壁の流れてくるスピードや間隔などの難易度を簡単に変更できるシステム。
* **判定システム**: （未定・後日決定）当たり判定（コライダー）ベースか、座標・角度計算ベースかを検証。

## 6. 今後のスケジュール・マイルストーン
* **Phase 1**: 技術検証（プロジェクター環境でのSlimeVR(OSC)データのUnityへの取り込みと、キャラクターへの反映）
* **Phase 2**: プロトタイプ作成（壁が迫ってきて、ポーズをとる基本サイクルの実装）
* **Phase 3**: 判定システムの実装と設定画面（難易度調整）の作成
* **Phase 4**: ブラッシュアップ（壁のバリエーション追加、UI/演出の強化）
